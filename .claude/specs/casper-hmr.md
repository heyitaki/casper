# casperHMR — true Swift/AppKit hot module reload

Status: **interview-finalized spec, gated on Phase 0 spike.** Target: Casper-only Debug builds. Owner: Casper fork.

This spec supersedes the design draft at `docs/casper-hmr.md`. Major deltas from that draft:

- Phase 0 spike validation is mandatory and explicit. **0a** proves `SWIFT_EXEC` fires AND the cmux Debug build still launches cleanly under whatever flag combo enables it. **0b** proves argv normalization works on real Xcode 26.5 captures. **0c** proves `dlopen` redirects existing call sites in already-loaded host code — symbol resolution alone is not enough.
- Build settings: new `Configs/Casper-Debug.xcconfig` carries **only** `SWIFT_EXEC`. Existing inline `OTHER_LDFLAGS = -Xlinker -interposable` and `SWIFT_COMPILATION_MODE = incremental` stay in `project.pbxproj` (moving them would either duplicate them under xcconfig precedence rules or require a destructive pbxproj edit, both worse than the additive xcconfig).
- Multi-instance state is per-tag at `~/.casper/hmr/<tag-slug>/`, where `<tag-slug>` follows the existing `sanitize_path` rule from `reload.sh` (`[a-z0-9-]` only, fallback `agent`). Untagged builds use `~/.casper/hmr/agent/`.
- Observer model: `CasperHMRReloadable` protocol (constrained `Self: NSObject`) with **no default `casperHMRReload()` body** — every conformer must implement it. Defaults are only for `register()`/`deregister()`. SwiftUI uses `.casperHotReload()` modifier (subscribes to `.casperHMRReloaded`); renaming to `.casperHMRReload()` is deferred to PR 3 to avoid coexistence churn.
- Out-of-envelope detection is **symbol-validated**: walk `__DATA_CONST,__interpose` AND `__DATA,__interpose`, then `dladdr(original_symbol_addr)` and compare the *mangled* symbol against a per-source-file symbol set pre-extracted via `nm -gU` from the captured `.o`. Zero entries → `no_interpose`; entries but no matches → `no_interpose_for_file`; `.o` missing (e.g. user wiped DerivedData) → `ok_unverified` if entries ≥1.
- Wrapper has **no short-circuit** — always writes JSONL. Filtering Casper-vs-non-Casper sources happens at daemon startup, not synchronously on every swiftc invocation (avoids duplicating the argv normalizer on the build's critical path).
- Atomicity: append uses `flock(LOCK_EX)` on `commands.jsonl.lock` always (POSIX only mandates regular-file write atomicity for pipes; XNU's small-write behavior is reliable in practice but not contractual). Startup compaction uses atomic temp+rename under the same flock.
- InjectionLite migration is three PRs: **PR 1** gates the new daemon behind `CASPER_HMR_NEW=1`; when the gate is on, InjectionLite is hard-disabled at boot (no FileWatcher, no log priming, no Obj-C bootstrap) so two compile pipelines never race inside dyld. **PR 2** flips the gate default. **PR 3** deletes InjectionLite and the bootstrap-time diagnostic observer at `CasperHotReload.swift:108-114`.
- Mandatory CI tests prove the dyld interpose mechanism end-to-end (Tests #6 and #7); not gated behind env vars.

## Summary

Casper iteration today requires a full `reload.sh` cycle for every source change, dropping terminal sessions, browser panels, and editor state. Existing community injection tools (InjectionLite, InjectionNext, Inject, HotSwiftUI) are broken on Xcode 26.3+ because `builtin-SwiftDriver` compiles in-process inside Xcode and `xcodebuild`, bypassing the `swiftc` subprocess they rely on. casperHMR replaces that with a Casper-owned pipeline: intercept `swiftc` via the Apple-supported `SWIFT_EXEC` build setting, capture per-file driver invocations to disk at build time, then on file save recompile the changed file to a `.dylib` and `dlopen` it so dyld's `__interpose` section swaps the symbol live. The pipeline is `#if DEBUG`-only, isolated to `Sources/Casper/HMR/`, and dead-stripped from shipped binaries. The win is reliability of recompile on Xcode 26.5 CLI workflows — the runtime mechanism is the same primitive InjectionLite uses.

## Requirements

1. **Phase 0 gate.** Before any other work lands, a 1-day spike must produce **end-to-end live behavior change** in a fixture host: (a) `SWIFT_EXEC` is honored under `reload.sh` xcodebuild on Xcode 26.5 (natively or with `SWIFT_USE_INTEGRATED_DRIVER=NO`) **AND**, with whatever flag combination made `SWIFT_EXEC` fire, the cmux Debug build itself runs to completion, the resulting `.app` launches, and the running app shows no "module not found" / "missing required module" / explicit-modules manifest errors in the cmux debug log. The known-hard interaction is that `SWIFT_USE_INTEGRATED_DRIVER=NO` is the only known way to force `SWIFT_EXEC` under xcodebuild 26.3+ but historically breaks Xcode 26's explicit modules — if it does in our toolchain, that is the no-go condition, not "JSONL is non-empty"; (b) captured argv replays cleanly through the argv normalizer (see §argv normalization) and produces a `.dylib`; (c) the fixture host — a pre-loaded executable that *already called* `foo()` and stored the result — calls `foo()` *again* after dlopen and observes the new return value. Symbol-resolves-to-new-code is not enough; the interpose section must redirect existing call sites in the host's already-loaded code. Anything less is "no-go" — pivot to SPM-subpackage capture path or abandon decision goes back to the user with the empirical evidence, not auto-resolved.
2. **Build-time capture.** A `casper-swiftc-wrapper` binary, vended at `Tools/Casper/swiftc-wrapper/`, intercepts every swiftc invocation during Debug builds and **always** writes a JSONL entry (no source-path-based short-circuit). Filtering Casper-vs-non-Casper sources synchronously inside the wrapper would force it to expand `@response.resp` and `-filelist <path>` files on the build's critical path — duplicating the daemon's argv normalizer (Req 16) on every swiftc invocation. Cost trade is N tiny appends at build time vs one O(N) walk at daemon launch; the launch-time filter (Req 13's validation pass + a `files contains anything under Sources/Casper/` predicate) is the right place. Wrapper logic:
    1. **Recursion guard.** If `CASPER_SWIFTC_WRAPPER_ACTIVE=1` is already in env, skip the JSONL append entirely and proceed straight to step 4. This guards against any nested invocation (e.g. swiftc spawning another swiftc that re-consults `SWIFT_EXEC` because some build-system layer re-injects it) and matches the "wrapper must be idempotent under recursion" defensive pattern. Set `CASPER_SWIFTC_WRAPPER_ACTIVE=1` in the *child* env passed to step 4.
    2. **Resolve real swiftc once.** Call `xcrun --find swiftc` *with `SWIFT_EXEC` removed from the child env* (xcrun itself does not consult `SWIFT_EXEC`, but we scrub anyway for defense), cache the result at `$HOME/.casper/hmr/tools/cache/real-swiftc-path` keyed by `DEVELOPER_DIR` to avoid the `xcrun` cost on every invocation. If the cache is stale or missing, run `xcrun` and rewrite. Do **not** path-resolve via `$PATH`; the canonical Swift toolchain location is governed by `DEVELOPER_DIR`.
    3. **JSONL append.** Build the full JSON line in memory, take `flock(LOCK_EX)` on `<state-dir>/commands.jsonl.lock`, open `<state-dir>/commands.jsonl` with `O_APPEND | O_WRONLY | O_CREAT`, write the line, close, release the flock. (POSIX only guarantees `O_APPEND`+`write(2)` atomicity for pipes/FIFOs; XNU's regular-file behavior for ≤PIPE_BUF writes is reliable in practice but not contractual, and flock cost is negligible at swiftc-invocation frequency.)
    4. **Exec the real toolchain.** `execve(real_swiftc_path, original_argv, child_env)` where `child_env` is `current_env` minus `SWIFT_EXEC` (so the child's own driver invocations don't loop back through us via `SWIFT_EXEC`) plus `CASPER_SWIFTC_WRAPPER_ACTIVE=1`. Pass `argv` through unchanged — wrapper never mutates compile flags. Wrapper's own exit status is whatever the execve'd swiftc exits with.
3. **Build settings.** A new `Configs/Casper-Debug.xcconfig` (additive file) carries **only** `SWIFT_EXEC = $(HOME)/.casper/hmr/tools/bin/casper-swiftc-wrapper` (out-of-tree to avoid in-repo `.build` artifacts; see §Files modified). `OTHER_LDFLAGS = -Xlinker -interposable` and `SWIFT_COMPILATION_MODE = incremental` are already inline in the Debug `XCBuildConfiguration` in `project.pbxproj` and stay there — moving them to the xcconfig would either duplicate them (precedence hazard: inline target settings override xcconfig when both set the same key without `$(inherited)`) or require a pbxproj edit to delete them, which fights the additive-over-modifying policy. The xcconfig is referenced from the Debug `XCBuildConfiguration` via `baseConfigurationReference`. Release config does not reference it. Phase 0 verifies `SWIFT_EXEC` is actually honored — if pbxproj somehow shadows the xcconfig value the spike catches it.
4. **Runtime daemon.** `CasperHMRDaemon` starts in `cmuxApp.init()` in Debug builds unless `CASPER_HMR_DISABLE=1` is in the environment OR the user has disabled it via the `Debug > Casper HMR` menu toggle (`@AppStorage("casper.hmr.enabled")` defaults to `true`).
5. **Watcher scope and repo-root resolution.** FSEvents watches `<repoRoot>/Sources/Casper/**.swift`. The receive-side filter rejects any event whose canonicalized path matches any of:
    - `<repoRoot>/Sources/Casper/HMR/**` — daemon's own source files; edits require `reload.sh`.
    - Anything under `<repoRoot>/.build/**`, `<repoRoot>/build/**`, `<repoRoot>/DerivedData/**`, `<repoRoot>/.derivedData/**` — SwiftPM and Xcode build outputs; defensive even though they're not under `Sources/Casper/` today (someone could symlink, or a future re-org could place generated Swift there).
    - Anything under a path component that starts with `.` (hidden dirs) — covers `.git`, `.swiftpm`, `.gradle`, etc.
    - Any `.swift` file whose **first line** is a generated-code sentinel: `// swiftlint:disable`/`// swiftlint:disable file`/`// Generated by`/`// swift-format-ignore-file`/`// @generated`/`// AUTO-GENERATED`/`// DO NOT EDIT` (case-insensitive). Generated files (`*.generated.swift`, Sourcery output, etc.) should not trigger swaps; the daemon never wins a race against the generator.
    - Anything where `realpath(<event.path>)` lands *outside* `<repoRoot>` (defends against a `Sources/Casper/Vendor/` symlink chain pointing into the user's home; we only swap code that lives in-tree).
   `repoRoot` resolves from the `CMUXTERM_REPO_ROOT` env var (already set by `reload.sh` line 699 / injected into tagged app `Info.plist` `LSEnvironment` at line 571). Missing env var → daemon writes **one final swap-event** with `result=miss_repo_root`, `path=""`, then disables itself and emits a `cmuxDebugLog("casper.hmr.no_repo_root")` line. The one-shot event is necessary so the Recent Swaps debug panel can show *why* HMR is silent instead of looking like it never started. Don't try to guess from `Bundle.main.bundleURL` — Dock-launched apps from `/Applications` won't have a meaningful relative path.
6. **Compile pipeline.** On a watched-file save, the daemon: looks up the captured `SwiftcInvocation`, **normalizes argv** (see §argv normalization), mutates to single-file primary mode + object emission, execs swiftc → `<hash>.o`, links via **`swiftc -emit-library -Xlinker -dylib`** (not raw `clang -dynamiclib`, so Swift autolink-extract + Swift runtime linkage are handled by the driver) → `<hash>.dylib`, ad-hoc signs per Req 18 (`codesign --sign -` with `--options=runtime` only if Phase 0 found it necessary), `dlopen`s with `RTLD_NOW | RTLD_GLOBAL`, then posts `Notification.Name.casperHMRReloaded` (only on `result=ok` or `result=ok_unverified`) with the source path in `userInfo`.

   **`<hash>` definition.** First 16 hex chars of `SHA-256(source_path ‖ 0x1f ‖ source_bytes ‖ 0x1f ‖ hash_compile_argv ‖ 0x1f ‖ hash_link_argv)`. `hash_compile_argv` is the post-normalization, pre-mutation argv from Req 16 — Req 16 strips the captured xcodebuild `-o <BUILT_PRODUCTS_DIR>/Foo.o` so the hashed argv carries no `-o`. `hash_link_argv` is the planned link argv with the daemon's `-o` value replaced by the literal `"$HASH$.dylib"`. Result: both halves are free of build-graph-specific paths (DerivedData, OBJROOT), so the short-circuit works across `reload.sh` cycles, not just within one session. Canonicalize by sorting repeatable flag groups (`-I`, `-F`, `-L`, `-framework`, `-l`, `-rpath`, `-Xfrontend …`) so flag-order churn doesn't cause misses. No circular self-reference: hashing happens before `-o …/<hash>.o`/`<hash>.dylib` are installed in step 6. 64-bit collision risk is negligible (~2³² distinct dylibs per session for a birthday).

   **Short-circuit semantics — `result=unchanged`, not `result=ok`.** If `<hash>` matches the last successful swap's hash AND `~/.casper/hmr/<tag-slug>/dylibs/<hash>.dylib` exists on disk, write swap-event with `result=unchanged`, do **not** post `.casperHMRReloaded` (matches Behavior step 13's rule against spurious view rebuilds), bail. Recent Swaps colors this gray; latency aggregation (Req 10) excludes `unchanged` from the p50/p95 window (microsecond short-circuits would hide real compile-latency regressions). The "and dylib exists on disk" clause is what makes the predicate fail closed against the launch-time wipe and in-session eviction below — post-wipe/post-evict first-edit always recompiles; the user never sees `unchanged` while host behavior has reverted to pre-swap.

   **Dylib-dir bounding.** `~/.casper/hmr/<tag-slug>/dylibs/` is wiped at daemon launch — the dominant bound. For long dogfood sessions, after every swap event the daemon scans the dir and if it returns >500 files **or** >500 MB sum-of-sizes, evicts oldest-mtime-first until both thresholds are below. Evicted dylibs stay loaded in-process — `dlclose` on an interposed dylib has undefined behavior. Eviction does not touch the `[CanonicalPath: PreviousHash]` cache; the short-circuit's disk-existence clause force-recompiles evicted entries automatically. **`.o` files in the same dir are not evicted** — tiny relative to dylibs and feed `nm` symbol extraction. Thresholds are constants in `CasperHMRConfig.swift`.
7. **Multi-instance isolation.** `CASPER_HMR_TAG` env var (set by `reload.sh --tag <foo>` per Req 15) selects the per-tag state dir at `~/.casper/hmr/<tag-slug>/`; dylib intermediates at `~/.casper/hmr/<tag-slug>/dylibs/`. Tag slug is produced by `reload.sh`'s `sanitize_path` at `scripts/reload.sh:146` (lowercase, non-`[a-z0-9]` runs collapse to `-`, empty input → `agent`). **`agent` is the build-time capture fallback only; the runtime daemon refuses to start under it** (see §Security posture's tagged-builds-only rule). Untagged `reload.sh` still exports `CASPER_HMR_TAG=agent` to avoid the path-malformed `~/.casper/hmr//commands.jsonl`, so writes are funneled into the sentinel dir but never consulted by a running app. **At runtime the daemon does not re-sanitize** — it reads `CASPER_HMR_TAG` verbatim, asserts `^[a-z0-9-]+$` and falls back to `agent` on failure (which then triggers the boot-time refusal). This avoids both shell-out cost on launch and silent drift from a parallel Swift `sanitize` reimpl. A code comment in `CasperHMRConfig.swift` points at `scripts/reload.sh:146` as the canonical rule.
8. **Observer model — required impl, not default body.** A `CasperHMRReloadable` protocol (constrained to `Self: NSObject`) with **no default `casperHMRReload()` body** — every conformer must implement it. The protocol provides only: (a) `register()` default that uses `objc_setAssociatedObject` to attach a `NSObjectProtocol` notification token for `.casperHMRReloaded` (idempotent; safe to call multiple times); (b) `deregister()` default that removes the observer. A `needsDisplay = true` default would be misleading correctness — it doesn't recreate cell views, rebind delegates, rebuild closures, reset constraints, or refresh menus. Per-view implementations are mandatory:
   - `CasperFindResultsView` → `outlineView.reloadData()` + `outlineView.needsDisplay = true` (existing pattern, keep).
   - `CasperEditorPortal` → controller's `updateFromConfig()` + `setNeedsLayout = true` (since the portal owns a STTextView with cached attributes).
   - `SidebarRevealStrip` (SwiftUI) → no protocol; uses the existing `.casperHotReload()` modifier.
   - Other adopters specify their own. The lint rule for new `Sources/Casper/**/*View.swift` requires both protocol adoption *and* a non-defaulted `casperHMRReload()` implementation; the codereview checklist enforces it.
   SwiftUI views continue to use the existing `@CasperInject` property wrapper + `.casperHotReload()` modifier, which now subscribes to `.casperHMRReloaded` instead of `INJECTION_BUNDLE_NOTIFICATION`. SwiftUI gets a default behavior because `id(observer.generation)` is the universally correct semantic (rebuild subtree). AppKit doesn't have an analogous universal nudge, hence no default.
9. **Out-of-envelope detection — symbol-validated, not entry-count-validated. `ok` is a mechanism guarantee, not a behavior guarantee.** See §Semantics for the user-facing implications. Detection here covers *whether the dylib's interpose section targets symbols we can attribute to the saved file* — it does not (and cannot, at link time) cover whether the user's edit class will produce a user-visible change. Some edit classes the daemon cannot detect from the dylib alone — **the dylib loads and the interpose section may even match, but the runtime effect is undefined**:
   - **Protocol conformance added / removed** on an existing type. The conformance metadata records are emitted into the dylib but the original type's witness-table pointer in the running process is unchanged. Subsequent generic dispatch through the new conformance may pick up either side depending on the call site.
   - **Stored property added** on a class. The dylib's allocator emits a larger instance size; existing instances allocated pre-swap retain the old size and the new property's storage offset reads garbage.
   - **Enum case added** to a `@frozen` or pattern-matched-by-pre-swap-code enum. Switch statements compiled before the swap have no arm for the new case and trap on `default`/unreachable.
   - **Vtable layout change** (added/removed/reordered non-final method on a non-final class). Subclasses compiled pre-swap dispatch through stale vtable slots.
   - **Generic specialization change.** The specialized symbol may differ from the unspecialized symbol's name; interpose may target one but not the other depending on which the caller resolved.
   - **`extension` method added** that previously dispatched statically. The new symbol exists in the dylib but the call site was statically resolved to the missing-method-error path or to a different overload at compile time.
   We don't detect these from interpose-section data — no reliable `__interpose`-level signal exists, and parsing both sides of the source diff would re-introduce the Xcode-frontend dependency this design avoids. Result is `result=ok` (mechanism succeeded) but the user may see no change or a crash. The Recent Swaps panel's `result=ok` is honest about *what happened in dyld*, not *what will happen next frame*. For diffs that add/remove stored properties or enum cases, fall back to `reload.sh`; Req 21's source-change classifier catches most of these pre-compile and emits `result=out_of_envelope_predicted`.

   Immediately post-`dlopen`: locate the dylib's mach header via `_dyld_image_count()` / `_dyld_get_image_header(i)` / `_dyld_get_image_name(i)` path-matching, then walk both `getsectiondata(header, "__DATA_CONST", "__interpose", ...)` and `getsectiondata(header, "__DATA", "__interpose", ...)`. Each entry is a `{replacement_addr, original_addr}` pair. Validate that ≥1 entry's `original_addr` resolves (via `dladdr`) to a symbol in the changed file. `dladdr` returns the **mangled** Swift symbol in `info.dli_sname` (e.g. `_$s4cmux17CasperFindResultsViewC4bodyQrvg`); `nm -gU` emits mangled names too, so the comparison is direct string match. **No demangling step; do not wire `swift-demangle`.** Symbol-name sets are extracted lazily via `nm -gU <original .o path>` on first save to each file and cached in `[SourcePath: Set<MangledSymbol>]` until daemon exit — avoids blocking app init on N×`nm` subprocesses. The `.o` path can disappear between capture and swap (user ran `xcodebuild clean` etc.). At swap time:
   - dylib has ≥1 interpose entry AND ≥1 entry's `dli_sname` is in the changed file's symbol set → `result=ok`, log matched symbols.
   - dylib has ≥1 interpose entry but the changed file's symbol set is **empty** (missing/unreadable `.o`) → `result=ok_unverified` — we cannot prove the entry targets a symbol declared in this file, but we have at least one swap-eligible entry, so the dylib *probably* swapped something. Logged with a `reason=missing_object_file` field; user should `reload.sh` to refresh capture.
   - dylib has ≥1 interpose entry but no entry matches a known symbol from the file → `result=no_interpose_for_file` (stale/unrelated interpose entries; edit didn't touch a swappable symbol in this file).
   - 0 entries → `result=no_interpose`.
   Log the specific symbols matched in the `cmuxDebugLog` line so the user can see *what swapped*.
10. **Diagnostic surfaces.** Every swap writes a `cmuxDebugLog` line, appends to `~/.casper/hmr/<tag>/events.jsonl`, and shows up in `Debug > Debug Windows > Casper HMR Recent Swaps`. The file is bounded by **a startup-time rewrite that keeps the last 1000 entries** — JSONL lines are variable-width, so there is no in-place truncate that preserves trailing entries. Implementation: at daemon launch, under `flock(LOCK_EX)` on `events.jsonl.lock`, read the file, keep the trailing 1000 lines, write to `events.jsonl.tmp.<pid>`, `rename` over `events.jsonl`. Daemon tracks p50/p95 swap latency over a rolling 100-event window, **excluding `result=unchanged` events** (they're microsecond short-circuits that would skew the metric downward and mask real compile-latency regressions). Surfaced in the same panel.
11. **Coalescing + timeout + file-stability.** FSEvents 100ms debounce; if a save arrives for a file with a compile in flight, cancel + restart. Hard 5s timeout on swiftc and clang subprocesses; on timeout, kill, log `casper.hmr.swap.timeout`, bail. Compiles run on a serial `DispatchQueue` (dyld dislikes concurrent dlopen of dylibs with overlapping interpose entries).

    **File-stability gate (defends against partial saves from atomic-rename / in-place-truncate / burst-write editor patterns).** After debounce and before normalization, take two `stat(2)` snapshots 50ms apart. **Compile proceeds only if both `(size, mtime)` pairs are byte-equal AND a `read(2)` of the file succeeded on the second sample.** If they differ, reset the debounce and re-check; bounded to 5 cycles (~750ms) before giving up with `result=unstable_file`. The `read(2)` check covers the temp-rename window where `stat` succeeds against the old inode but the new one hasn't been linked yet. ~50ms typical added latency, well inside the `CASPER_HMR_P95_BUDGET_MS + 500ms` budget.
12. **InjectionLite coexistence then removal — three PRs, mutually-exclusive compile pipelines.** Two pipelines must never run concurrently: both would dlopen dylibs with overlapping interpose entries and dyld's resolution order is undefined.
    - **PR 1 (this spec):** Land `CasperHMRDaemon` behind `CASPER_HMR_NEW=1`. Gate **off** (default): only InjectionLite runs, byte-identical to today. Gate **on**: new daemon runs; InjectionLite hard-disabled at boot — `casperHotReloadBootstrap()` is a no-op, `casperPrimeInjectionLogsPath()` and `casperCaptureStdoutForHotReload()` are not called, and the bootstrap-time `INJECTION_BUNDLE_NOTIFICATION` observer at `CasperHotReload.swift:108-114` does **not** register. SwiftUI views (`.casperHotReload()` / `@CasperInject`) subscribe to both `.casperHMRReloaded` and `INJECTION_BUNDLE_NOTIFICATION` so they light up regardless of which pipeline is live — safe because only one notification fires per gate setting.
    - **PR 2 (after ≥1 week dogfood, ≥80% successful swap rate):** Flip gate default off→on; leave InjectionLite code present but unreachable.
    - **PR 3:** Delete `InjectionLite` SPM dep, `casperPrimeInjectionLogsPath()`, `casperCaptureStdoutForHotReload()`, the Obj-C bootstrap shim, the bootstrap observer at `CasperHotReload.swift:108-114`, and the `INJECTION_BUNDLE_NOTIFICATION` subscriptions in `.casperHotReload()` / `@CasperInject`. Rename `casperHotReloadBootstrap()` → `casperHMRBootstrap()` and `.casperHotReload()` modifier → `.casperHMRReload()` (deferred from PR 1 to avoid churn during coexistence).
13. **Stale `.jsonl` recovery (atomic temp+rename).** On daemon startup: (1) take an exclusive `flock(LOCK_EX)` on `commands.jsonl.lock`; (2) read `commands.jsonl`; (3) validate each `SwiftcInvocation`'s primary source path exists and dedup; (4) write the compacted set to `commands.jsonl.tmp.<pid>`; (5) `rename("commands.jsonl.tmp.<pid>", "commands.jsonl")` (POSIX atomic on same filesystem); (6) release lock. Wrappers always open `commands.jsonl` with `O_APPEND` so the rename does not invalidate any in-flight append fd — the renamed-away file is unlinked when the writer closes its fd. Compaction is launch-only; we never compact while the app is running, which avoids the wrapper-vs-daemon racey case during a hot rebuild.
14. **Release safety.** Release builds do not reference `Casper-Debug.xcconfig`. `casper-swiftc-wrapper` is not invoked. `CasperHMRDaemon.swift` is `#if DEBUG`-only. Verification is **Test #11's three-surface check** (mangled-symbol `nm -gU` prefixes for the HMR-owned types return zero, the `casperHMRBuildSentinel` constant is absent from `strings` output, and `otool -L` does not list `InjectionLite` post-PR-3). The bare `strings | grep casperHMR` formulation that appeared in earlier drafts is case-fragile (misses `CasperHMR`) and substring-fragile (collides with unrelated `_dlopen`-style symbols); see Test #11 for rationale.
15. **`reload.sh` integration.** `CASPER_HMR_TAG=<sanitized-tag-slug>` must propagate along **two distinct paths**; `reload.sh` exposes env to two different child processes and there is no single shared "xcodebuild env block":
    - **Build-time (wrapper sees it):** `export CASPER_HMR_TAG="$TAG_SLUG"` after `TAG_SLUG` is computed at `scripts/reload.sh:338`, inserted between `XCODEBUILD_ARGS+=(build)` at `:444` and `XCODEBUILD_LOCK=` at `:446`. (`:494` is the heredoc close, not a usable insertion point.) The shell `export` propagates into `xcodebuild`'s env, then into `SWIFT_EXEC` subprocess env. The build-setting positional args in `XCODEBUILD_ARGS` at `:423-444` are **not** a usable carrier — they're xcconfig overrides, not env, and Xcode 26's driver does not consistently forward them to `SWIFT_EXEC` children. Untagged builds (`TAG_SLUG` empty) explicitly `export CASPER_HMR_TAG="agent"` to avoid `$HOME/.casper/hmr//commands.jsonl`.
    - **Runtime (Dock-launched app sees it):** inject `CASPER_HMR_TAG` into the tagged bundle's `Info.plist` `LSEnvironment` via the existing `set_plist_env` helper at `:206`, mirroring `CMUXTERM_REPO_ROOT` at `:571`.
    - **Tag slug source:** always `sanitize_path` at `:146` (the same function that produces `TAG_SLUG` at `:338`); charset `[a-z0-9-]`, fallback `agent`. The daemon does not re-sanitize (Req 7) — `reload.sh` produces the slug exactly once and embeds it in both carriers.
16. **Argv normalization + path canonicalization.** The daemon parses captured argv into a structured `SwiftcInvocation` before mutation. Normalization handles:
    - **Expand:** response files (`@foo.resp` inline), `-filelist <path>` (read file, expand to individual paths).
    - **Strip:** pre-existing `-primary-file` flags (we install our own); batch-mode multi-`-primary-file` (replace with a single one for the changed file); the captured `-o <build-graph-path>` (xcodebuild always emits one into `BUILT_PRODUCTS_DIR`/`OBJROOT`; leaving it in would (a) collide with the daemon's `-o` in step 6 and (b) make `<hash>` build-graph-specific); dependency-output flags `-emit-dependencies-path`, `-emit-reference-dependencies-path`, `-serialize-diagnostics-path` (would write into build-graph paths).
    - **Keep:** explicit-module flags (`-explicit-swift-module-load-list`, `-Xfrontend -disable-implicit-swift-modules` — both required under Xcode 26), autolink flags, bridging headers (`-import-objc-header`), `-working-directory`.
    - **Pass through unchanged:** anything else.

    **Path canonicalization — both sides must agree.** Captured argv source paths may or may not be symlink-resolved; FSEvents delivers absolute paths but does not resolve symlinks. Without reconciliation, a file at `/Users/aki/code/cmux/Sources/...` in argv but watched via `/private/var/.../symlink/Sources/...` produces `result=miss_argv` on every save. Run `URL(fileURLWithPath:).resolvingSymlinksInPath().standardizedFileURL.path` (or `realpath(3)`) on **all three** of: wrapper writing `files: [...]` to `commands.jsonl`, daemon receiving FSEvents, daemon performing the argv-map lookup. The argv-map key is a `CanonicalPath` newtype constructed only via the canonicalizing init, making "raw `String` as map key" uncompilable.

    The normalizer is a pure function with golden-file tests against real Xcode 26.5 argv captures (see §testing).
17. **Link flag scraping + linkage model.** The daemon scrapes link-relevant flags from the original argv (`-target`, `-arch`, `-isysroot`, `-mmacosx-version-min`, all `-F`/`-framework`/`-weak_framework`/`-L`/`-l`/`-rpath`, all SPM product-library `-l` entries) and composes the link with `swiftc -emit-library -Xlinker -dylib -Xlinker -undefined -Xlinker dynamic_lookup` + scraped flags. swiftc handles `swift-autolink-extract` internally.

    **Linkage model — load-bearing.** Casper source lives in the cmux Swift module (`-module-name cmux`), not a separate module. The daemon reuses the captured `-module-name cmux`, so the single-file `.o` is compiled against the cmux module interface and emits external references to every cmux-internal symbol the edited file calls — sibling Casper files, sibling stock-cmux files, anything in the module that isn't `private`/`fileprivate`. None of those symbols are in `<hash>.dylib`; all must resolve at dlopen time against the **already-loaded host** via `dynamic_lookup`. Three enablers in this codebase:
    - **Host carries `-Xlinker -interposable`** (Debug `OTHER_LDFLAGS`), which both gives every user-code function an interpose-eligible call-site stub and keeps export visibility broad enough for `dynamic_lookup` to find `internal` mangled symbols. Without it, many cmux-internal symbols would be `__TEXT` private and unreachable from the dylib.
    - **Dylib uses `dynamic_lookup`** so the linker emits unbound external references; dyld resolves at `dlopen`.
    - **Swift mangling is stable across same-toolchain `swiftc` invocations**, so unbound refs in the dylib match host symbol table byte-for-byte. A mid-session Xcode upgrade silently breaks this — `events.jsonl` logs `result=dlopen_fail` with dyld's "symbol not found"; recovery is `reload.sh`.

    Coverage by access level: `private`/`fileprivate` resolve inside the recompiled `.o`, no host resolution needed. `internal` cross-file calls go through `dynamic_lookup` — the load-bearing case. `public`/`open` Apple-framework calls resolve through `dynamic_lookup` against the framework's loaded image. Same primitive InjectionLite uses, but the spec states it explicitly so the implementer doesn't infer. Phase 0c step 12 proves only the public-symbol single-file path; **step 12a is required** to prove the `internal` cross-file case in a two-file fixture.
18. **Dylib state dir + signing + quarantine.** Dylibs written to user-owned, non-quarantined `~/.casper/hmr/<tag-slug>/dylibs/`. After link: (a) `xattr -d com.apple.quarantine <hash>.dylib 2>/dev/null || true` (defensive — usually no attr, but downloads/iCloud-synced repos can have it); (b) `codesign --sign - --timestamp=none --identifier casper-hmr-<hash> <hash>.dylib` (ad-hoc required for dyld on arm64 macOS 14+). Failure → `result=sign_fail`. **`--options=runtime` is a Phase 0 binary decision recorded as a source constant**, not a runtime probe: Phase 0 sign+loads both ways and picks the one that loads cleanly. Hardened-runtime only matters for shipped binaries and can interact awkwardly with library validation for ad-hoc local dylibs.
19. **Captured env subset — replay echoes xcodebuild-injected vars back.** The wrapper captures an env subset; the daemon **replays it as the child env when execing swiftc**, not the daemon's own env. `xcodebuild` injects `BUILT_PRODUCTS_DIR`, `OBJROOT`, `SYMROOT`, `SOURCE_ROOT`, `MODULE_CACHE_DIR` into compile children but they are not in the user's shell env, so without replay the daemon would rebuild Swift modules from scratch on every save. Starting allowlist: `DEVELOPER_DIR`, `SDKROOT`, `TOOLCHAINS`, `PATH`, `HOME`, `TMPDIR`, `SOURCE_ROOT`, `BUILT_PRODUCTS_DIR`, `OBJROOT`, `SYMROOT`, `MODULE_CACHE_DIR`, `SWIFT_MODULE_CACHE_PATH`, `CLANG_MODULE_CACHE_PATH`, `LANG`, `LC_ALL`, plus anything matching `^(SWIFT_|XCODE_|DT_)`. Phase 0 fixes the final allowlist by recording what swiftc demands on a clean Casper-file recompile; misses surface as "module not found" / "missing required module" and are added iteratively. Child `cwd` is the captured `-working-directory` flag (Req 16) or the captured `cwd` field, in that order — never the daemon's `PWD`.
20. **Capture fingerprint — reject stale `commands.jsonl` after toolchain/project drift.** Each entry carries: `xcode_build_version` (`xcodebuild -version | tail -1` cached at wrapper start), `sdkroot_real_path` (`realpath $SDKROOT`), `wrapper_version` (semver compiled into the binary), `pbxproj_mtime_ns` (mtime of `GhosttyTabs.xcodeproj/project.pbxproj`), `build_settings_hash` (SHA-256 of `env_subset` values). At daemon startup, after Req 13's validation, if `xcode_build_version` or `wrapper_version` differs from the daemon's own runtime values, **the entire `commands.jsonl` is rejected** — a partial mismatch usually means an Xcode upgrade mid-session and unchanged fingerprints are stale in ways we can't detect. The daemon logs `casper.hmr.refused reason=fingerprint_drift xcode_was=<x> xcode_now=<y>`, emits a `result=miss_fingerprint` swap event, and refuses to compile until `reload.sh` rebuilds. Without this gate, Xcode upgrades or `xcconfig` changes silently produce `dlopen_fail`/`compile_fail`/missing-module errors that look like "HMR is broken." Partial-mismatch handling (e.g. only `pbxproj_mtime_ns` changed): drop only affected files, keep the rest. Phase 0 records the actual `xcode_build_version` string format.
21. **Source-change classification — cheap pre-compile triage.** Before invoking swiftc, the daemon runs a sub-100µs regex classifier on current bytes vs bytes at last successful swap (or daemon-launch bytes for the first save). Not AST-based — that would re-introduce a swiftc-frontend dependency on the critical path. Triggers on **whole-line additions/deletions** (in-line modifications are conservatively "body-likely") containing:
    - `import ` at column 0
    - `class `, `struct `, `enum `, `actor `, `protocol ` at line start — new type
    - `^extension\s+\w+\s*:\s*\w` — new conformance
    - `var ` / `let ` at type-body indent — new stored property
    - `case ` at type-body indent — new enum case
    - `@inlinable`, `@_transparent`, `@frozen`, `@objc(`, `@dynamicCallable`, `@dynamicMemberLookup`, `dynamic func`
    - `@MainActor`, `nonisolated`, `isolated ` — actor-isolation changes

    On hit: emit `result=out_of_envelope_predicted`, `reason=<token>` without recompiling. Recent Swaps panel colors this orange to distinguish from `no_interpose` (post-compile). User gets the "needs `reload.sh`" signal in <1ms instead of waiting 800-1500ms for a compile that lands as `no_interpose` anyway. False positives are acceptable — the cost is one unneeded `reload.sh`, the benefit is killing 30s of "why didn't my edit take effect" debugging. Phase 0 sub-phase 0c step 14b tunes the regex set if FP rate >20%. Classifier lives in `Sources/Casper/HMR/CasperHMRSourceClassifier.swift`, golden-file tested.
22. **Main-actor enforcement.** Compile/link/sign/dlopen runs on the serial compile queue `DispatchQueue(label: "casper.hmr.compile", qos: .userInitiated)` — explicitly non-`@MainActor`. Three boundaries hop back to main:
    - **Notification post.** Wrap `NotificationCenter.default.post(name: .casperHMRReloaded, ...)` in `DispatchQueue.main.async`. Non-main post crashes inside AppKit reload callbacks on the first main-thread-only API.
    - **Recent Swaps panel update.** Panel view-model is `@MainActor`. Daemon writes `events.jsonl` off-main but updates the in-memory `RollingLatencyWindow` and `@Published` event-list via `Task { @MainActor in ... }`.
    - **`@AppStorage` toggle observation.** `UserDefaults.didChangeNotification` may fire off-main; the read is thread-safe but the resulting FSEvents teardown/recreation must hop to main per FSEvents' main-runloop assumption.

## Design

### Data model

**Captured invocation (`~/.casper/hmr/<tag>/commands.jsonl`):** JSONL, one object per line.
```jsonc
{
  "schema": 1,
  "ts": 1715600000.123,
  "tag": "casper",
  "cwd": "/Users/aki/code/cmux",
  "files": ["Sources/Casper/Search/CasperFindResultsView.swift", ...],
  "argv": ["/Applications/Xcode-26.5.app/.../swiftc", "-frontend", ...],
  "env_subset": {
    "DEVELOPER_DIR": "...",
    "SDKROOT": "...",
    "TOOLCHAINS": "...",
    "PATH": "...",
    "HOME": "...",
    "TMPDIR": "...",
    "SOURCE_ROOT": "...",
    "BUILT_PRODUCTS_DIR": "...",
    "MODULE_CACHE_DIR": "...",
    "SWIFT_MODULE_CACHE_PATH": "...",
    "...": "..."
  }
}
```
Append-only; daemon dedups by content-addressed source-set key on read.

**Swap event (`~/.casper/hmr/<tag>/events.jsonl`):** JSONL, bounded to 1000 entries.
```jsonc
{
  "ts": 1715600001.456,
  "path": "Sources/Casper/Search/CasperFindResultsView.swift",
  "duration_ms": 412,
  "result": "ok" | "ok_unverified" | "unchanged" | "dlopen_pending" | "compile_fail" | "link_fail" | "sign_fail" | "dlopen_fail" | "image_lookup_fail" | "no_interpose" | "no_interpose_for_file" | "out_of_envelope_predicted" | "miss_argv" | "miss_repo_root" | "miss_fingerprint" | "unstable_file" | "timeout",
  "interpose_entries": 7,
  "matched_symbols": ["_$s4cmux17CasperFindResults…F", "..."],
  "reason": "missing_object_file",
  "stderr_tail": "…last 4kb of stderr if not ok…"
}
```

**Daemon in-memory state:**
- `[CanonicalPath: SwiftcInvocation]` map, rebuilt on launch from the validated `commands.jsonl`. The key type is `CanonicalPath` (Req 16's newtype) — raw `String` is uncompilable here so the "did I forget to canonicalize?" bug class is unrepresentable.
- `[CanonicalPath: PendingCompile]` for in-flight cancellation (same canonicalization rule).
- `[CanonicalPath: PreviousHash]` (referenced by Req 6's short-circuit predicate): the last successfully-computed `<hash>` per source path. Populated on every swap that runs to step 5a (including `unchanged` short-circuits — re-recording the same hash is a no-op). Used by step 5b's hash-equality check. **Not** persisted to disk; the launch-time `dylibs/` wipe (Req 6) and this cache being empty are jointly what force first-edit-after-launch to always recompile.
- `[CanonicalPath: Set<MangledSymbol>]` (referenced by Req 9): the symbol-name set per source file as emitted by `nm -gU <captured .o path>`. Populated lazily on the *first* save to each file (not on daemon launch — see Req 9's lazy-extraction rationale). Survives until the daemon exits. Missing/unreadable `.o` keeps the entry absent and feeds the `result=ok_unverified` branch.
- `RollingLatencyWindow<Duration>` (100-entry ring) for p50/p95 metric — `result=unchanged` events are not appended (Req 10).

### Behavior

**Build-time (xcodebuild → wrapper → swiftc):**

1. `reload.sh --tag foo` invokes `xcodebuild` with `CASPER_HMR_TAG=foo` in env.
2. The Casper-Debug xcconfig sets `SWIFT_EXEC` to the wrapper binary path.
3. For every Swift source under the Casper module, xcodebuild's driver consults `SWIFT_EXEC` and invokes the wrapper.
4. Wrapper reads its argv and the captured env subset (Req 19), takes `flock(LOCK_EX)` on `commands.jsonl.lock`, appends a single JSONL entry to `~/.casper/hmr/$CASPER_HMR_TAG/commands.jsonl`, releases the lock, then `execv`s `xcrun --find swiftc` with the original argv. The wrapper does no further interpretation — source-set-key computation and dedup happen at daemon startup (Req 13).
5. Build completes. The running binary now has `~/.casper/hmr/$CASPER_HMR_TAG/commands.jsonl` available.

**Runtime (file save → swap):**

1. FSEvents fires for `Sources/Casper/Search/CasperFindResultsView.swift`.
2. Daemon's 100ms debounce timer expires (or restarts if more events arrive).
3. Daemon looks up the file in its argv map. Miss → log `casper.hmr.miss path=…`, write swap-event with `result=miss_argv`, bail.
4. Daemon cancels any in-flight compile for the same file, then queues onto the serial compile queue.
5. **Normalize argv** via the `SwiftcInvocation` parser (Requirement 16): expand `@response.resp`, expand `-filelist`, strip pre-existing `-primary-file`/batch-mode entries, preserve `-working-directory` + explicit-modules + bridging headers, strip dependency-output flags.
5a. **Compute `<hash>`** per Req 6: SHA-256 over `(source_path ‖ 0x1f ‖ source_file_bytes ‖ 0x1f ‖ hash_compile_argv ‖ 0x1f ‖ hash_link_argv)`. `hash_compile_argv` is the just-normalized argv (no `-o` yet); `hash_link_argv` is the canonicalized link argv with the daemon-private `-o` replaced by `"$HASH$.dylib"`. First 16 hex chars.
5b. **Short-circuit.** If `<hash>` matches the last successful swap's hash for this path AND `~/.casper/hmr/<tag-slug>/dylibs/<hash>.dylib` exists, re-record the hash in `[CanonicalPath: PreviousHash]` (explicit no-op write maintains the data-model invariant), emit `result=unchanged`, **don't** post `.casperHMRReloaded`, bail. Hash matches but dylib missing (post-launch-wipe first-edit) → fall through to step 6.
6. **Mutate** normalized argv: install `-primary-file <saved-file>`, `-emit-object`, `-o ~/.casper/hmr/<tag>/dylibs/<hash>.o` (substituting the `<hash>` just computed in 5a). Req 16's normalizer has already stripped the captured xcodebuild `-o` so there is no duplicate-`-o` collision at this step. All `-target`, `-sdk`, `-swift-version`, `-module-name`, `-I`, `-F`, `-D`, `-Xfrontend`, framework search paths, explicit-module flags pass through.
7. Exec swiftc with 5s timeout. Non-zero exit or timeout → write swap-event with `result=compile_fail` (or `result=timeout`), log stderr tail to debug log, bail.
8. **Link** via scraped flags (Requirement 17): `swiftc -emit-library -Xlinker -dylib -Xlinker -undefined -Xlinker dynamic_lookup <scraped -target/-arch/-isysroot/-mmacosx-version-min/-F/-framework/-weak_framework/-L/-l/-rpath> <hash>.o -o <hash>.dylib`. Same 5s timeout. Failure → `result=link_fail`. (swiftc handles `swift-autolink-extract` and Swift runtime linkage internally, which raw `clang -dynamiclib` does not.)
9. **Ad-hoc sign**: `codesign --sign - --timestamp=none --identifier casper-hmr-<hash> <hash>.dylib`, with `--options=runtime` appended *only if* Phase 0 determined it's required on this macOS version (Req 18). Required on arm64 since macOS 14; dyld rejects unsigned dylibs.
10. **Pre-dlopen breadcrumb (crash containment).** Before `dlopen`, append a provisional `events.jsonl` line: `result=dlopen_pending`, `path=<saved-file>`, `hash=<hash>`, `ts=<now>`, then `fsync`. This survives a crash: if dlopen'd code crashes the app before the final event, post-mortem shows which dylib loaded last. On success of 11–15, write the final event; the provisional line stays as a redundant breadcrumb. Startup compaction (Req 10) treats `dlopen_pending` as a regular transitional result. Then `dlopen("<hash>.dylib", RTLD_NOW | RTLD_GLOBAL)`. Nil → `result=dlopen_fail`, log `dlerror()`, bail. **`RTLD_GLOBAL` is required** — interpose entries in an `RTLD_LOCAL` image only apply to lookups originating from that image and later-opened images, missing the call-site rewriting we need in the host. InjectionLite uses `RTLD_GLOBAL` for the same reason. Downside (subsequent unrelated dlopen's seeing our swapped symbols) is benign — our swapped symbols are mangled cmux-module Swift names and the only other dlopens are SPM/Apple frameworks loaded long before us. Phase 0 step 12 cross-checks via two consecutive swaps.
11. **Locate the loaded image header**: iterate `_dyld_image_count()`; for each `i`, compare `String(cString: _dyld_get_image_name(i))` against the dylib path we just opened (canonicalized). On match, `header = _dyld_get_image_header(i)`. Image not found → `result=image_lookup_fail` (shouldn't happen if dlopen succeeded but defensive).
12. **Walk interpose sections and validate target symbols**: get entries from both `__DATA_CONST,__interpose` and `__DATA,__interpose`. Zero entries → `result=no_interpose`. Non-zero entries → for each entry, `dladdr(entry.original_symbol_addr, &info)` to resolve `info.dli_sname` (which on Apple platforms is the mangled Swift symbol — no demangling step). String-compare against the changed file's pre-extracted mangled-symbol set (Requirement 9). Branches:
    - `.o` file present, ≥1 entry matches the file's symbol set → `result=ok`, `matched_symbols=[…]`.
    - `.o` file absent (user wiped DerivedData since the capture build) and ≥1 entry exists → `result=ok_unverified`, `reason=missing_object_file`. Daemon proceeds with the swap; we just can't prove the entry targets this file specifically.
    - `.o` file present, entries exist, none match the file's symbol set → `result=no_interpose_for_file`.
    - 0 entries → `result=no_interpose`.
13. `ok` or `ok_unverified` → post `.casperHMRReloaded` with `userInfo["path"]` = saved file path, `userInfo["result"]` and `userInfo["matched_symbols"]` for observers that want to log specifics. `unchanged`, `no_interpose`, `no_interpose_for_file`, and all `*_fail`/`timeout`/`miss_*`/`image_lookup_fail` results → log only; do not post the notification (avoids spurious view-rebuilds when nothing actually swapped).
14. Observers wake: SwiftUI views bump `@StateObject` generation; AppKit views call their conformer-defined `casperHMRReload()` (Req 8 forbids a default body — each conformer owns its own reloadData / setNeedsLayout / delegate rebind / cell-prototype invalidation / closure rebuild; no separate `casperHMRReconfigure()` hook).
15. Daemon updates the rolling p50/p95 metric and notifies the Recent Swaps debug panel.

**Daemon shutdown:** automatic via process exit. Dlopen'd dylibs leak by design (the OS reaps them on exit). `~/.casper/hmr/<tag>/dylibs/` is wiped on next daemon launch.

## Edge cases & error handling

- **New file added.** Wrapper hasn't seen it → argv map miss → log `casper.hmr.miss`, `result=miss_argv`. User runs `reload.sh` to populate.
- **File renamed.** Map carries `OldName.swift`, no entry for `NewName.swift` → `result=miss_argv`. Startup validation (Req 13) drops `OldName.swift` next launch. Recovery: `reload.sh`. Called out separately because rename is easy to forget as a capture-invalidating event.
- **Signature change / stored property added / @inlinable edit.** **Unsupported and not reliably detectable at the dyld layer.** Can land as any of: `compile_fail` (mangled mismatch), `link_fail` (unresolved sibling), `dlopen_fail` (incompatible image), `no_interpose`/`no_interpose_for_file` (loads but empty/wrong-target interpose), `ok` followed by crash (vtable/layout mismatch — undetectable from the dylib per §Semantics), or `ok` with silent stale behavior. Req 21's classifier catches most of these pre-compile with `result=out_of_envelope_predicted`; anything missed falls into the post-compile categories above. Either way, user runs `reload.sh`. The spec does not promise a single tidy result code for this class.
- **`.o` missing at swap time** (post-clean / wiped DerivedData). Daemon can't pre-extract the symbol set. ≥1 interpose entry → `result=ok_unverified`, `reason=missing_object_file`. Notification posted; user can `reload.sh` to refresh.
- **`CMUXTERM_REPO_ROOT` missing.** Daemon logs `casper.hmr.no_repo_root`, disables itself. User launches via `reload.sh`.
- **Quarantine attribute on dylib.** Pipeline runs `xattr -d com.apple.quarantine` before codesign. Failure silent.
- **`codesign` refuses ad-hoc sign.** `sign_fail`. Phase 0 picked the `--options=runtime` setting for this codebase; a different machine's policy may still reject.
- **Concurrent wrapper writes.** Each takes `flock(LOCK_EX)` on `commands.jsonl.lock` for the write — no reliance on POSIX-undefined small-write atomicity. Daemon compaction takes the same flock.
- **swiftc/clang/codesign hang.** 5s timeout per process → kill, log `timeout`, daemon stays healthy.
- **Two rapid saves to the same file.** Debounce coalesces. Second save mid-compile → SIGTERM the in-flight swiftc, drop the dylib, restart.
- **Two saves to different files concurrently.** Serial queue. Bursts may exceed p95 for the trailing edit.
- **Daemon crash.** Views continue with last-swapped code; user restarts the app to recover. No crash-recovery state.
- **`commands.jsonl` references moved/deleted file.** Startup validation drops missing entries, rewrites deduped.
- **`SWIFT_USE_INTEGRATED_DRIVER=NO` required.** If Phase 0 finds the native path fails but fallback works, bake `SWIFT_USE_INTEGRATED_DRIVER = NO` into `Casper-Debug.xcconfig`. Re-verify explicit-modules still build.
- **Stale `.jsonl` vs fresh code.** Startup validation catches missing files but not stale flags from an older Xcode. Workaround: any non-trivial xcconfig/Xcode upgrade requires a fresh `reload.sh`.
- **Two cmux instances same tag.** Share `commands.jsonl`. Last-build-wins by content-addressed source-key — probably fine. Non-supported scenario.
- **Release-build leak detection.** Post-release CI runs Test #11's three-surface check (mangled `nm -gU` + `casperHMRBuildSentinel` strings + `otool -L`/Info.plist). Any hit fails the build.

## Semantics — what HMR can and can't swap

`result=ok` means "dyld accepted the dylib, `__interpose` was applied, and ≥1 entry's `original_symbol_addr` resolves to a symbol declared in the saved file." Strong on mechanism, weak on user-observable outcome. State that interpose cannot reach:

- **Already-retained closures.** A `let onTap = { ... }` captured into `NSButton.target/action` or SwiftUI `Button(action:)` keeps the *old* closure body — interpose redirects calls to the named function, not values copied out of one.
- **Cached delegate references.** `tableView.delegate = self` retains the *pre-swap* vtable for cached `objc_msgSend` IMPs. Conformers needing refresh must re-assign the delegate / recreate data-source proxy / drop+rebuild cell prototypes inside their own `casperHMRReload()`.
- **SwiftUI view identity.** If `.id(...)` is computed from pre-swap captured constants, SwiftUI reuses identity (and state graph). `@CasperInject` + `.casperHotReload()` force-rotates `id()` per-modifier-instance to dodge this; views computing their own `id(...)` from in-body constants need to opt in.
- **`static let` / global `let` initializers.** Run-once; interpose can't re-run them. Edits load but never take effect this process lifetime.
- **`lazy var` already accessed.** Same shape as `static let`, per-instance.
- **Objects constructed pre-swap.** Stored-property defaults, `init()` bodies, constructor-wired values stay pre-swap. Only fresh allocations pick up new init bodies.
- **Inlined call sites.** `@inlinable`, `@_transparent`, generic specializations get baked into callers at compile time — bypass interpose. Same as InjectionLite.
- **Apple-vendored symbols.** `-interposable` covers user-code emission only. Inlined Foundation/AppKit/SwiftUI initializers at user-code call sites don't swap.

`result=ok` asserts "the next *fresh* call through the named symbol(s) executes the new code" — not "user sees different behavior next frame." For body-of-existing-AppKit-view edits reached via `casperHMRReload()`, those overlap. For everything else the user may need to trigger a fresh code path (close+reopen, scroll, click) or fall back to `reload.sh`. Same operating model as every other Swift HMR tool.

## Non-goals

- Not a general HMR system for stock cmux. The pipeline lives entirely under `Sources/Casper/HMR/` + `Tools/Casper/swiftc-wrapper/` + `Configs/Casper-Debug.xcconfig`.
- Not a Release feature. All code paths are `#if DEBUG`-only; Release config does not reference the xcconfig.
- Not a replacement for `reload.sh`. Full rebuilds remain the path for: new files, signature changes, stored property additions, asset/xcstrings/Info.plist/entitlements changes, SPM dependency changes, `@inlinable`/`@_transparent` edits, C/Obj-C/Zig (cmuxd, ghostty), and protocol conformance changes.
- Not multi-process. Hot-reloads target a single running Casper instance per tag. Tagged isolation + `reload.sh` remain the path for parallel instances.
- Not a Swift Package Manager subpackage of Casper. If the Phase 0 spike fails, the SPM-subpackage pivot is the *next* spec, not part of this one.
- Not a notification/banner UX surface. Failures live in the debug log + Recent Swaps panel only.

## Security posture

`casperHMR` reads source files from disk, compiles them with the user's swiftc toolchain, ad-hoc codesigns the resulting dylib, and `dlopen`s it into the running app's address space. That is a deliberate code-execution channel and the access controls reflect it. Boot-time refusals (any of these → daemon disables itself with a `casper.hmr.refused reason=…` log line; no events.jsonl write, no FSEvents watcher, no compile queue):

- **`#if DEBUG` only.** `CasperHMRDaemon.swift`, `casper-swiftc-wrapper/`, `Casper-Debug.xcconfig`, and every call site are wrapped in `#if DEBUG`. Release builds physically lack the code path; the leak test (Req 14, Testing #11) is the enforcement.
- **Tagged builds only.** The daemon refuses to start when `CASPER_HMR_TAG` is missing OR equals `"agent"` (the untagged-fallback sentinel) OR the running app's bundle identifier is the production `co.cmux.cmux` rather than a tagged Debug bundle id. The intent is "Dock-launched production cmux never hot-reloads, even by accident." Tagged Debug bundle ids are produced by `reload.sh`'s tag derivation; Phase 0 verifies the bundle-id check against an actual tagged `.app`.
- **Repo root must be under `$HOME`.** `CMUXTERM_REPO_ROOT` is canonicalized (`URL(fileURLWithPath:).resolvingSymlinksInPath()`) and must resolve to a path with `$HOME` (also canonicalized) as a strict ancestor — same `String(filePath).hasPrefix(home + "/")` test, both canonicalized. Refuse if the canonical repo root is under `/tmp`, `/private/tmp`, `/Applications`, `/Library`, `/System`, `/Volumes`, or any path outside the user's home. The threat model: a tagged Debug build is launched against a repo the user did not intend (e.g. a tmpfs scratch dir touched by another process, or an Applications-installed sample). Refusal is silent (the log line is the only signal) and the rest of the app boots normally.
- **Wrapper binary must be owned by the user.** `stat(2)` the resolved `SWIFT_EXEC` path at daemon launch; refuse if `st_uid != geteuid()` or the file is world-writable (`S_IWOTH` set) or group-writable by a group the user is not in. This guards against a hostile `~/.casper/hmr/tools/bin/casper-swiftc-wrapper` planted by another local user — the daemon would otherwise replay the wrapper's-captured-argv into a child swiftc and trust the env subset that was recorded.
- **State dir permissions.** `~/.casper/hmr/<tag-slug>/` and its children (`commands.jsonl`, `events.jsonl`, `dylibs/`) are created with mode `0700`; the daemon `fchmod`s on open to repair drift. Refuse to load any dylib whose path resolves outside `~/.casper/hmr/<tag-slug>/dylibs/` after `realpath(3)` — guards against a symlink-injection that would have us load an attacker-controlled dylib.
- **No network access.** The daemon does not open sockets, does not fetch source or argv from anywhere off-disk, does not consult any remote service. The threat surface is local-disk-and-toolchain only.

What we explicitly do **not** harden against: a local attacker with write access to the user's checked-out source tree. That attacker can already drop a Swift file that runs arbitrary code at the next `reload.sh`; casperHMR doesn't widen that surface. The hardening above is exclusively against (a) accidental production-bundle activation, (b) wrong-repo activation, (c) cross-user wrapper / state-dir tampering on shared machines.

1. **Tagged reload succeeds end-to-end.** `./scripts/reload.sh --tag hmr-pr1 --launch` exits 0, the `.app` launches, the main window paints, the cmux debug log at `/tmp/cmux-debug-hmr-pr1.log` shows no `module not found` / `missing required module` / explicit-modules errors in the first 10 seconds, and `~/.casper/hmr/hmr-pr1/commands.jsonl` exists with ≥10 entries covering files under `Sources/Casper/`.
2. **Edit-to-swap on a SwiftUI body refreshes the live view without session loss.** With `CASPER_HMR_NEW=1` set, edit `CasperFindResultsView.swift`'s `body` to change a visible string, save, and observe the change reflected in the open Find sidebar. **Budget = `CASPER_HMR_P95_BUDGET_MS + 500ms`**, where `CASPER_HMR_P95_BUDGET_MS` is the Phase-0c-step-14-measured compile/link/sign p95 ceiling (likely 800–1500 ms for a real Casper view). The +500ms covers the UI-propagation portion: FSEvents debounce (100ms), observer wakeup, SwiftUI view-graph diff, and AppKit redraw. **Acceptance #2 measures end-to-end save→render, not compile-only**, so the budget tracks the compile budget rather than asserting a fixed wall-clock number that would either be too loose (hiding regressions) or too tight (failing on jitter). If end-to-end exceeds budget but compile p95 stays inside `CASPER_HMR_P95_BUDGET_MS` (recorded in `events.jsonl`), the UI-propagation tail is the regression — diagnose separately. Terminal sessions, browser panels, and editor scroll state are preserved across the swap (the whole point of HMR vs `reload.sh`).
3. **Edit-to-swap on an AppKit outline triggers `casperHMRReload()`.** Edit a row-rendering branch in `CasperFindResultsView` (the AppKit `outlineView(_:viewFor:item:)` path), save, scroll/click to force re-layout, observe the new branch executing. The Recent Swaps panel shows `result=ok` with a non-empty `matched_symbols` array including a mangled symbol from `CasperFindResultsView`.
4. **New file produces `result=miss_argv`.** Create a new `.swift` file under `Sources/Casper/`, save it, observe a swap event with `result=miss_argv` in `events.jsonl` and the Recent Swaps panel. The app does not crash; subsequent edits to *known* files keep working. User runs `reload.sh` to repopulate.
5. **Release artifact has no HMR code reachable.** A `cmux.xcarchive` produced via `Release` configuration passes **all three** of Test #11's surfaces: (a) `nm -gU cmux.app/Contents/MacOS/cmux` returns zero matches for the mangled prefixes of `CasperHMRDaemon` / `CasperHMRSourceClassifier` / `CasperHMRReloadable`; (b) `strings cmux.app/Contents/MacOS/cmux` does not contain the `casperHMRBuildSentinel` constant baked into `CasperHMRConfig.swift`; (c) `otool -L cmux.app/Contents/MacOS/cmux` does not list `InjectionLite` (post-PR-3) and `Info.plist` does not contain `SWIFT_EXEC` or `casper-swiftc-wrapper`. This is Test #11 phrased as an acceptance check; the older bare `strings | grep casperHMR` form is rejected as case- and substring-fragile.
6. **Disabling the menu toggle stops swaps.** With HMR active and the daemon running, click `Debug > Casper HMR > Enabled` to uncheck it; save a watched file; verify no new event appears in `events.jsonl` and no `.casperHMRReloaded` posts. Re-check the toggle, save again, verify a swap event appears.
7. **Pre-existing user workflow undisturbed when `CASPER_HMR_NEW` is unset.** Without the gate env var, `reload.sh --tag …` behavior is byte-identical to today: InjectionLite runs, `casperPrimeInjectionLogsPath` / `casperCaptureStdoutForHotReload` fire, no new daemon, no swap events. Verified by diffing the `/tmp/cmux-debug-<tag>.log` first-second output against a pre-PR-1 baseline.

## Open questions

- **Sparkle / signed builds.** None of the HMR code ships in Release. **Test #11** (Release-build leak test — three-surface check: mangled `nm -gU` symbols, `casperHMRBuildSentinel` string, `otool -L` for InjectionLite/Info.plist for SWIFT_EXEC) is the verification; Test #8 is the capture-smoke test against a Debug build, which is the wrong target for this claim. Sparkle update flow itself is unaffected.
- **CI builds.** CI runs Release builds, where `Casper-Debug.xcconfig` is not referenced and `SWIFT_EXEC` is unset. Should be invisible to CI. Verify on first PR.
- **Foundation framework symbol coverage.** A subset of Foundation-bridged Swift symbols may not pick up `-interposable` stubs (the spec for `-interposable` covers user-code emission, not vendored Apple symbols). If a Casper view's body calls e.g. `NSAttributedString` initializers that get inlined, those bodies won't swap. Same envelope as InjectionLite.
- **What if Xcode 27 ships official HMR.** Retirement is mechanical: drop `Sources/Casper/HMR/`, remove `Configs/Casper-Debug.xcconfig`, remove `Tools/Casper/swiftc-wrapper/`, repoint observers at the official notification. Tracked in `docs/casper-fork.md` deletion condition.

## Phase 0 spike — execution detail

The spike is the gate. **1-day budget** (expanded from the original half-day because of the interpose-proof requirement and argv-normalizer realism work). Concrete steps:

### Sub-phase 0a: capture (≤2 hr)

1. Write `Tools/Casper/swiftc-wrapper/Sources/casper-swiftc-wrapper/main.swift` (~50 lines): take `flock(LOCK_EX)` on `<state-dir>/commands.jsonl.lock`, append a JSONL entry to `<state-dir>/commands.jsonl` (always — no source-path short-circuit per Req 2), release lock, `execv` real swiftc.
2. `swift build -c release --scratch-path "$HOME/.casper/hmr/tools/build/" --package-path Tools/Casper/swiftc-wrapper/`, then `install -m 0755 "$HOME/.casper/hmr/tools/build/release/casper-swiftc-wrapper" "$HOME/.casper/hmr/tools/bin/casper-swiftc-wrapper"`. No in-repo `.build/` directory is created.
3. Create `Configs/Casper-Debug.xcconfig` with only `SWIFT_EXEC = $(HOME)/.casper/hmr/tools/bin/casper-swiftc-wrapper`.
4. Add the xcconfig to the Debug `XCBuildConfiguration` for the `cmux` target via `baseConfigurationReference`.
5. Run `./scripts/reload.sh --tag hmr-spike`.
6. Inspect `~/.casper/hmr/hmr-spike/commands.jsonl`. Expected: ≥1 entry per changed Casper file with full argv (target, sdk, module-name, F, I, explicit-modules flags).
7. If empty: set `SWIFT_USE_INTEGRATED_DRIVER = NO` in the xcconfig, rerun, re-inspect.
8. **Build must still succeed end-to-end and launch cleanly under whatever flag combo made `SWIFT_EXEC` fire.** This is the under-recognized hard half: forcing the legacy driver via `SWIFT_USE_INTEGRATED_DRIVER=NO` historically breaks Xcode 26's explicit modules (which cmux uses — `-explicit-swift-module-load-list` appears in real argv). Verification: after a green xcodebuild, run the built `.app`, watch `/tmp/cmux-debug-hmr-spike.log` for ≥10s, grep for `module not found`, `missing required module`, `cannot load module`, `unknown module`, `swift::abort`, `Module compiled with Swift X cannot be imported by Swift Y`. Any hit, or any non-trivial crash before the main window paints, is a **no-go** on that flag combo. Try without `SWIFT_USE_INTEGRATED_DRIVER=NO` first; if `SWIFT_EXEC` doesn't fire natively *and* the legacy-driver workaround breaks the build, that's the abort condition for the spec — bring evidence (xcodebuild log + tail of the cmux debug log + the failing flag combos tried) back to the user. Do not auto-pivot.

### Sub-phase 0b: argv normalizer realism (≤2 hr)

9. Take one captured entry, run it through a draft `parseArgv` → `SwiftcInvocation` → mutate → `compileArgv`. Make sure response-file expansion, `-filelist` expansion, and pre-existing `-primary-file` stripping all work on the real captured argv. If the argv format is fundamentally different from expectation (e.g. `builtin-SwiftDriver` emits a flag form `-frontend` can't accept), document and triage.

### Sub-phase 0c: interpose proof (≤4 hr) — **the real gate**

10. Create a fixture: a tiny Swift exec target `hmr-spike-host` with `Sources/main.swift` that calls `print(foo())` in a loop with `Thread.sleep(1)` between, and `Sources/Lib.swift` defining `public func foo() -> String { "v1" }`. Build with `-Xlinker -interposable`, run it; observe `v1 v1 v1 …`.
11. Edit `Lib.swift` to `return "v2"`. Replay the mutated normalized argv → `.o`. Link via `swiftc -emit-library -Xlinker -dylib -Xlinker -undefined -Xlinker dynamic_lookup` + scraped flags. Codesign **twice**, once `codesign --sign - --timestamp=none --identifier casper-hmr-spike <path>` (no hardened runtime) and once with `--options=runtime` added; attempt `dlopen` against each variant and record which **(a) loads cleanly AND (b) causes the existing `foo()` call sites to flip to "v2" per step 12.** `dlopen` returning a non-nil handle only proves dyld accepted the signature — it does not prove the interpose section was applied. Prefer the simpler (no `--options=runtime`) variant; only if it loads but step 12 shows no swap, OR it fails to load entirely, fall back to `--options=runtime` and re-verify both conditions. Hardcode the winning combination into `CasperHMRDaemon`.
12. From inside the running host (via a debugger or a built-in `signal`-handler-triggered dlopen), `dlopen` the new dylib. Observe stdout flips from `v1` to `v2` for subsequent iterations. **This is the gate**: if existing call sites in the already-loaded host code don't switch to the new function, the entire spec is invalid and we pivot or abandon.
12a. **Cross-file `internal` linkage proof.** Extend the fixture: add `Sources/Helper.swift` with `internal func helper() -> String { "h1" }`, change `Lib.swift`'s `foo()` to `return helper() + "/v1"`. Both files compile into the same Swift module (`-module-name hmrspike`). Build, run, observe `h1/v1`. Now edit *only* `Lib.swift` to `return helper() + "/v2"` and run the daemon's compile pipeline on `Lib.swift` alone — `Helper.swift` is untouched and not recompiled. The resulting dylib has an unbound external reference to `helper`'s mangled symbol; verify (`nm -u <hash>.dylib | grep helper`) the reference is unbound. `dlopen` the dylib, call `foo()`, expect `h1/v2`. **If dyld fails to resolve `helper` (stderr "symbol not found")** the design is broken for any real Casper edit that calls into a sibling file, and we must either (a) confirm the host build line actually carries `-Xlinker -interposable` and a sufficient export visibility, or (b) pivot the spec to "only edits that don't cross file boundaries are supported," which is much weaker. Recording the actual dyld stderr and the mangled `helper` symbol in the spike notes is mandatory whether step succeeds or fails. **Both step 12 and step 12a must pass** for the Phase 0 gate to flip green; passing 12 alone is not enough.
13. Walk the loaded image with `_dyld_get_image_header` + `getsectiondata` for `__DATA_CONST,__interpose` and `__DATA,__interpose`. For each entry pair, `dladdr` the `original_symbol_addr` and verify `info.dli_sname` (a **mangled** Swift symbol — no demangling) string-matches an entry in `Lib.swift`'s symbol set extracted via `nm -gU Lib.o`. Confirm ≥1 matched entry exists for `foo`. If the sections are empty even though stdout flipped, or if stdout doesn't flip even though entries match, document — the detection heuristic needs revision or there's an alternative mechanism in play.
14. **Measure real Casper compile latency.** Use captured argv for a real Casper view (e.g. `CasperFindResultsView.swift`) — not the toy `Lib.swift`, because real argv carries explicit-modules flags, bridging headers, framework search paths, full SPM linkage. Run compile+link+sign 20× back-to-back (touch source between runs to defeat caching). Record p50/p95. Set `CASPER_HMR_P95_BUDGET_MS = ceil(p95_measured × 1.5)` in `CasperHMRConfig.swift`. Test #9 asserts against this; the Recent Swaps panel displays it.
14a. **Generic-heavy SwiftUI body proof — the real Casper class of edit.** Toy fixtures use plain functions; the production hot path is SwiftUI bodies with `some View`, generics, `@ViewBuilder`, `@MainActor` isolation — they compile differently and can interact with `-interposable` in surprising ways (Swift's specializer may emit specialized + generic stub symbols, interpose may only redirect one). Pick a real Casper SwiftUI view — `SidebarRevealStrip.swift` (small body, `some View`, `@MainActor`, `@ViewBuilder`). Replicate as `SwiftUIProbe.swift` in the spike host; embed via `NSHostingView(rootView: SwiftUIProbe())` in an `NSWindow`. Edit one line (e.g. `Text("a")` → `Text("b")`), run the pipeline, force `id()` rotation as `.casperHotReload()` does, visually verify "b". `nm -u <hash>.dylib | grep -i swiftui` should show SwiftUI-internal unbound refs resolved at dlopen via `dynamic_lookup`; any that *don't* resolve is the design failure mode. If swap visually applies but Req 9's symbol-validated detection misses (likely: SwiftUI body's mangled symbol differs from `nm -gU` extraction), either refine the heuristic or broaden symbol-set extraction (include `_$s...body...` mangling). Recording the actual mangled body symbol is mandatory.
14b. **Source-change classifier hit-rate measurement — tune the Req 21 regex set.** Without this step the classifier ships untuned and Req 21's FP-rate gate has no measurement. Enumerate Casper diffs: `git log --since="3 months ago" --diff-filter=M --name-only --pretty=format: -- 'Sources/Casper/**/*.swift' | sort -u`, then `git log -p -- <file>` per file. Hand-label each diff "body-only" vs "signature-changing". Run the classifier and record (a) **recall** = fraction of true `out_of_envelope` diffs flagged; (b) **FP rate** = fraction of body-only diffs incorrectly flagged. Targets: recall ≥ 90%, FP rate < 20%. If either misses: tighten `var `/`let ` indent rules for FP, broaden attribute set for recall. Re-measure. Record tuned regex set + measured pair in spike notes and at the top of `CasperHMRSourceClassifier.swift`. If FP can't get below 20% after tuning, flip Req 21's default to "classifier emits warning and proceeds with compile" via a `classifierMode: .gate | .advisory` constant in `CasperHMRConfig.swift`.

### Go/no-go

- All three sub-phases green → **go**, full spec executes.
- 0a green, 0b green, 0c fails → live behavior swap doesn't work; pivot to either ShaftUI-style `@_dynamicReplacement` approach (separate spec) or abandon.
- 0a fails → SPM-subpackage pivot decision goes back to the user.

Decision is recorded in this file's frontmatter (`Status:`) and a new section in `docs/casper-fork.md`.
